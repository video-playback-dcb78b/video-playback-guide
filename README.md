<a id="stage"></a>
## 先记录失败阶段

记下是整个网站打不开，还是可以登录、看封面但点击播放报错；如果已经起播，再记录是固定时刻失败还是随机缓冲。选择自己有观看权限的一段短内容，避免用正在付费或直播中的任务反复试验。

记录设备、播放方式、时间、所选画质和错误提示。不要仅用“测速很快”代替这些信息：测速目标与视频数据来源未必相同，短时峰值也不能说明长时间传输稳定。

如果普通网页也加载失败，先处理基础网络或代理连接，暂停播放器专项排查。只有视频失败时，继续缩小到内容、播放应用和数据传输阶段。

<a id="start"></a>
## 首页能开但视频不能开始

先阅读平台显示的具体错误。账户未登录、会员不含该内容、内容不可用和网络请求超时，处理方式不同。网络服务费用不包含影音会员；更换代理选项不能补足内容授权。

确认播放器加载过程在客户端记录中是否出现相应连接。播放使用的目标可能不止首页域名，因此首页可用不能证明所有播放请求均已通过。只核对失败时刻的目标和出站，不把整个平台的所有地址一律加入未知规则。

可以用平台允许的另一条短内容作一次对照。同账户其他内容正常而特定内容失败时，先查内容权限或平台状态；所有内容都不能起播时，再核对应用、浏览器和连接路径。不要通过安装陌生解码插件或关闭证书检查来强行播放。

<a id="buffer"></a>
## 能够起播但持续缓冲

先暂停其他设备的大下载、云备份和系统更新，再测试同一片段。仅暂停自己有权控制的任务，记录暂停前后差异。如果改善，说明同时传输可能影响体验，不能据此认定服务商限速。

接着把画质降低一级，固定该档位观看一小段。低档稳定、高档不稳定，说明当前条件不适合该档持续传输；先使用稳定画质，再继续排查网络或账户条件，不把它描述为已测得精确带宽。

若低档也反复中断，检查同一时刻其他小请求是否失败。在保存工作后，通过软件正常流程重建连接，再做同一短测试。只在原配置中有其他可用选项时做一次单项对照，避免连续切换导致播放器不断重新建立会话。

<a id="experiment"></a>
## 怎样做有效的画质和网络对照

每次只改一项：先固定设备、视频片段和画质，比较两个有权使用的网络；或者固定网络与内容，只比较浏览器和平台认可的 App。不要同时改网络、节点、画质和浏览器，否则结果无法解释。

保持观察窗口相近，并标注是否命中本地缓存。已缓存的片段播放流畅，不能证明新的数据传输已经恢复。必要时选相近长度的未观看片段，但不要为了避缓存反复下载整部视频。

测试会产生真实流量。账户剩余不多时，先停止长时间播放和全节点测速，查看套餐的统计周期，再用低画质短任务验证。不要让排障本身耗尽额度。

<a id="player"></a>
## 平台提示和播放器问题

出现明确版权、会员或地区授权提示时，按平台支持说明处理，不将其包装成普通连接故障。若提示浏览器版本、受保护内容或设备兼容性，核对平台自己的兼容要求与系统更新渠道。

只有一个浏览器异常时，可在保留账号资料的前提下用干净的临时浏览环境做一次对照；需要登录时只在真实平台输入凭据。若临时环境正常，再逐项检查扩展或该站点设置，不必先清空所有网站数据。

下载、离线缓存与在线播放可能有不同限制，不能以一种方式成功推断另一种必然正常。也不要使用来源不明的播放地址解析器处理含账户凭据的链接。

## 反馈信息与恢复

反馈用“可以起播，固定画质约两分钟后缓冲；同设备低档位正常”比“视频很卡”更有用。附具体时间、客户端模式、播放方式、脱敏错误和做过的单项对照，隐藏私人观看记录、账户标识和带签名的媒体 URL。

测试结束恢复原先需要的连接设置和暂停任务。如果网络正常但平台持续返回业务错误，联系平台；如果连接日志显示出站错误，则交给实际网络服务支持。恢复标准是原片段能够持续播放并完成需要的操作，而不只是首页恢复。
